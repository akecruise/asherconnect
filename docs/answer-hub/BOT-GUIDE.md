# BOT GUIDE — บอทใช้คลังคำตอบอย่างไร (โครง — เนื้อหาเต็มตาม Phase 15, 25)

## ลำดับการตอบของบอท (หลัง Phase 15)
1. ลูกค้าส่งข้อความ → ระบบตัดสินใจเดิม (decide_reply ใน SQL) ยังทำงานเหมือนเดิมทุกอย่าง
2. ก่อนเรียก AI สร้างคำตอบ บอทถามคลังคำตอบก่อน (`ah_bot_recommend`)
3. ถ้ามีคำตอบที่ผ่านตัวกรองทั้งหมด → ใช้คำตอบนั้น (ข้อมูล live จาก ERP ถูกแทนค่าแล้ว)
4. ถ้าไม่มี → fallback: AI สร้างเองจาก project-data เดิม (พฤติกรรมเดิม ไม่เปลี่ยน)

## เงื่อนไขที่บอทใช้คำตอบได้ (ครบทุกข้อเท่านั้น)
- [ ] status = approved
- [ ] audience = bot หรือ both
- [ ] bot_auto_answer = true (admin เปิดเอง — คำตอบที่มาจาก learning เกิดมาเป็น false เสมอ)
- [ ] อยู่ในช่วง valid_from – valid_to
- [ ] ข้อมูลที่ binding ต้องใช้ resolve สำเร็จทั้งหมด
- [ ] source ที่ผูกไว้เปิด "อนุญาตให้บอท" (bot_allowed)

**ข้อใดขาด = บอทไม่ตอบด้วยข้อความนั้น → ตอบแบบเดิมหรือส่งต่อมนุษย์ (requires_human_review)**
บอทห้ามเดาตัวเลข ห้ามสร้างราคา ห้ามสร้างโปรโมชั่น ห้ามเดาจำนวนห้องว่างเด็ดขาด

## Fallback & Human handoff
- คลังไม่มีคำตอบ + AI ไม่มั่นใจ → ไหลเข้า flow handoff เดิม (notify ทีมขาย)
- ข้อมูล required ขาด (เช่นยังไม่มีราคาในระบบ) → ไม่ตอบเรื่องนั้นอัตโนมัติ

## Safety Rules (สรุป)
- บอทอ่านอย่างเดียว ผ่านประตูเดียว (`ah_bot_recommend`) ไม่มี SQL ไม่มีการเขียนฐาน
- ทุกการตอบของบอทถูกบันทึก usage (actor_type=bot, action=auto_send)
- สวิตช์ปิดทั้งระบบ: `ANSWER_HUB_BOT_ENABLED=false` → กลับไปพฤติกรรมเดิม 100% ทันที
