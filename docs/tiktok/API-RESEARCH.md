# TikTok Business Messaging API research for @ashercondo

Checked 2026-09-23. Sources below are TikTok/ByteDance first-party documentation only. This is an API feasibility assessment, not evidence that @ashercondo or this project's developer app has been approved or authorized.

## Evidence and access

TikTok's [API for Business overview](https://ads.tiktok.com/resources/help/article/marketing-api?lang=en) identifies Business Messaging API as a product for sending and receiving TikTok direct messages. The [Business Messaging overview](https://business-api.tiktok.com/portal/docs?id=1832184079395841) says it is for *authorized Business Accounts* through API-integrated platforms. TikTok's documentation portal rendered a JavaScript-only shell in the text browser, but the first-party documentation service returned the page contents through `https://business-api.tiktok.com/gateway/api/doc/client/node/get/?identify_key=c0138ffadd90a955c1f0670a56fe348d1d40680b3c89461e09f78ed26785164b&doc_id=<ID>&language=ENGLISH`. The `doc_id` values in the citations are the pages actually checked; the first-party [documentation tree](https://business-api.tiktok.com/gateway/api/doc/client/platform/tree/get/?identify_key=c0138ffadd90a955c1f0670a56fe348d1d40680b3c89461e09f78ed26785164b) identified them. This read-only documentation access does **not** grant production API or @ashercondo account access.

## Actual availability and approval

- The API is not available on behalf of Business Accounts whose TikTok **sign-up region** is the EEA, Switzerland, or UK. Rest-of-world Business Accounts can be served only by developers who pass TikTok's Data Security & Privacy Review (DSPR). US-sign-up Business Accounts additionally require the US data security review and execution of the USDS Addendum. A successful account authorization alone does not bypass a regional or developer-review block. TikTok defines region by the Business Account's sign-up location, not the developer's location. [Access to Business Messaging API](https://business-api.tiktok.com/portal/docs?id=1832184145137922)
- The developer must have an approved developer app and valid App ID before applying. TikTok says a new app application can include `Ad Account Management`, `CTX Events Management`, and `Measurement` permissions; Business Messaging access follows the separate review. The application starts at TikTok's [intake form](https://bytedance.sg.larkoffice.com/share/base/form/shrlg7vFArGhg9V20neYCEwIKrb). TikTok says it initiates review within 10 working days after submission; DSPR normally takes 2–4 weeks. Review status is manually handled and not visible in the developer portal for self-serve developers. These are TikTok estimates, not a guaranteed approval date. [Access process](https://business-api.tiktok.com/portal/docs?id=1832184145137922); [DSPR](https://business-api.tiktok.com/portal/docs?id=1832184206708737)
- The API supports TikTok Business Accounts, including Registered Business Accounts (RBA); personal accounts are ineligible. TikTok Shop Messaging is a separate system. TikTok recommends RBA for more tools but does not state RBA is required for this API. [Access FAQ](https://business-api.tiktok.com/portal/docs?id=1832184145137922)
- **@ashercondo status: unverified.** No TikTok developer-portal, app-approval, DSPR result, TikTok account type/sign-up-region, account authorization, or live token evidence was available in this research. Therefore production availability for @ashercondo cannot be asserted. In particular, being in Thailand now would not by itself prove the account's TikTok sign-up region or app approval. The concrete go/no-go checks are app approval and Business Messaging scope, DSPR approval (plus US review/Addendum if the account signed up in the US), eligible account type and sign-up region, and successful owner authorization. [Access requirements](https://business-api.tiktok.com/portal/docs?id=1832184145137922); [authorization](https://business-api.tiktok.com/portal/docs?id=1832184159540418)

## Authorization, scopes, and token lifecycle

- The developer selects the `Business Messaging` permission in the app, supplies an app logo and TikTok-account-holder redirect URL, then shares the TikTok account holder authorization URL from **My Apps → App Detail → Basic Information**. The owner must approve four displayed permissions: send messages/interactions on the account's behalf; read inbox messages; read account type; and read/manage inbox messages. TikTok also says to select the `TikTok Accounts` permission if the account-holder URL is missing. An optional `state` parameter is echoed on redirect. Previously authorized users may be redirected without a new code; `disable_auto_auth=1` forces the authorization screen. [Authorization guide](https://business-api.tiktok.com/portal/docs?id=1832184159540418)
- TikTok's [API reference](https://business-api.tiktok.com/portal/docs?id=1735713875563521) maps `/business/message/send/` and `/business/message/media/upload/` to **Business Messaging Send**, conversation/message listing and media download to **Business Messaging Read**, and webhook configuration to **No permission needed** at the endpoint level. The [token response example](https://business-api.tiktok.com/portal/docs?id=1832184175482945) contains `message.list.send`, `message.list.read`, `message.list.manage`, and `user.account.type` among its scopes. Treat the approved app and actual token scopes as authoritative for this account; an example token is not proof of @ashercondo's grants. `/tt_user/token_info/get/` inspects authorized scopes. [Authentication](https://business-api.tiktok.com/portal/docs?id=1832184175482945); [token inspector](https://business-api.tiktok.com/portal/docs?id=1765927978092545)
- The redirect's `code` is exchanged at `POST https://business-api.tiktok.com/open_api/v1.3/tt_user/oauth2/token/` with JSON `client_id`, `client_secret`, `grant_type: authorization_code`, `auth_code`, and `redirect_uri` matching the configured redirect. This account-holder code is valid **10 minutes and once only**. The response includes `access_token`, `refresh_token`, `open_id`, `scope`, and expiries; use `open_id` as `business_id` in messaging requests. The short-term access token lasts **one day**; the refresh token lasts **one year**. Renew at `POST /tt_user/oauth2/refresh_token/` using `client_id`, `client_secret`, `grant_type: refresh_token`, and `refresh_token`. An expired refresh token requires owner reauthorization. [Authentication and exact request/response](https://business-api.tiktok.com/portal/docs?id=1832184175482945)

## Webhooks: configuration, verification, payload, echoes

- Configure once **per developer app** after business authorization, rather than once per authorized account: `POST https://business-api.tiktok.com/open_api/v1.3/business/webhook/update/` with JSON `app_id`, `secret`, `event_type: DIRECT_MESSAGE`, `callback_url`. The guide says this receives events for all businesses authorizing that app. `GET /business/webhook/list/` with `app_id`, `secret`, `event_type` reads the configuration; `POST /business/webhook/delete/` removes it. Set the Business Account to accept DMs from **Everyone** before authorization; otherwise its owner may have to accept message requests manually before webhooks arrive. [Webhook subscription](https://business-api.tiktok.com/portal/docs?id=1832190670631937); [create](https://business-api.tiktok.com/portal/docs?id=1832184470423554); [get](https://business-api.tiktok.com/portal/docs?id=1832184488625234); [delete](https://business-api.tiktok.com/portal/docs?id=1832184497985537)
- The Business Messaging guide links to TikTok's [webhook verification procedure](https://business-api.tiktok.com/portal/docs?id=1759978341579777): read `TikTok-Signature` (`t=<Unix-seconds>,s=<hex signature>`), compute hex HMAC-SHA256 over `timestamp + "." + JSON.stringify(request body)` with the developer app secret, compare signatures, then enforce an acceptable timestamp age. TikTok's sample uses **5 seconds as an example**, not a documented mandatory tolerance. The shared [webhook delivery specification](https://business-api.tiktok.com/portal/docs?id=1759977800177665) says HTTPS POST JSON, prompt HTTP 200 acknowledgement, retries for up to 72 hours with exponential backoff when 200 is absent, and best-effort at-least-once delivery; processing should be idempotent. The guide does not specify a separate Business Messaging verification handshake/challenge.
- Top-level webhook JSON has `client_key`, `event`, `create_time` (seconds), `user_openid` (the authorized business `open_id`), and `content` **as a serialized JSON string**. For `im_receive_msg` and `im_send_msg`, parsed `content` can include `conversation_id`, `message_id`, `timestamp` (milliseconds), `from_user`/`to_user` roles and IDs, `type`, type-specific `text.body`, `image.media_id`, `video.media_id` or shared-post information, `is_follower`, `auto_message_type`, and `message_tag.source`. `source` values include `APP`, `WEB`, `API`, `OTHERS`, `UNKNOWN_SOURCE`. [Business Messaging webhook schemas](https://business-api.tiktok.com/portal/docs?id=1832190670631937)
- `im_send_msg` is TikTok's event for a message sent by the business, so outbound events can be echoed back to the integration. Its `message_id` and `message_tag.source` can be used for correlation; the source schema does **not** promise a separate client idempotency key. `im_receive_msg` covers user messages from outside EEA/Switzerland/UK. The `im_receive_msg_eu` event for users in those regions contains only receiver/business identity and timestamp, **not sender, conversation ID, message ID, or body**. Do not treat it as an actionable inbox message. The guide also documents `im_referral_msg`, `im_mark_read_msg`, automatic-message updates, and high-intent-comment events. [Event schemas](https://business-api.tiktok.com/portal/docs?id=1832190670631937)

## Send, reply windows, and history

- A normal conversation starts with a user message; the business is prohibited from initiating a DM to someone who has not started a conversation. TikTok documents Comment-to-Message as a separate `direct_reply` path with narrow eligibility, including Business Accounts registered in **Vietnam, Indonesia, or Thailand**, first-level comment on the business's video, reply within 48 hours, no earlier DM reply to that comment, no DM interaction with the commenter in the prior 24 hours, and commenter over 18. Do not assume @ashercondo qualifies without checking its registration and setting. [DM guide](https://business-api.tiktok.com/portal/docs?id=1832184236919810); [send reference](https://business-api.tiktok.com/portal/docs?id=1832184403754242)
- For **non-mutual-follow** API conversations, the dedicated limits guide says: after the user's first message, up to **10 business messages in the following 48 hours**; after the user replies, an unlimited number of business messages within 48 hours of each latest user reply; after more than 48 hours without a user reply, at most **three additional business messages** until the user replies again. TikTok does not state in this guide how mutual-follow conversations are limited. The send endpoint's introductory note summarizes a 10-per-48-hours rule and differs in wording from the dedicated guide's unlimited active window; the dedicated guide is more specific about non-mutual follow, so live behavior should be verified if this distinction matters. [Dedicated messaging limits](https://business-api.tiktok.com/portal/docs?id=1854823717597185); [send reference note](https://business-api.tiktok.com/portal/docs?id=1832184403754242)
- `POST /business/message/send/` requires `Access-Token`, JSON, `business_id`, and (for a normal send) `recipient_type: CONVERSATION`, `recipient: <conversation_id>`, `message_type`. Supported outbound types are `TEXT` (`text.body`, maximum **6,000 characters**), `IMAGE` (`image.media_id`), `SHARE_POST` (`share_post.item_id`, only the business's own posts), `TEMPLATE` (Q&A button/link card), and `SENDER_ACTION` (`TYPING` or `MARK_READ`). Text and image cannot be combined. To quote an existing message, use `referenced_message_info.referenced_message_id` with a **text** reply to an original `TEXT`, `IMAGE`, or `SHARE_POST` message. The response contains `data.message.message_id`; it is empty for sender actions. [Send endpoint and examples](https://business-api.tiktok.com/portal/docs?id=1832184403754242)
- `GET /business/message/conversation/list/` requires `business_id` and `conversation_type` (`STRANGER` for unaccepted/unanswered request, `SINGLE` after business reply); `limit` is 1–100, default 100; `cursor` and `has_more` paginate. Only conversations from the **past 90 days** are accessible. Results include `conversation_id`, `update_time`, and optional ad/short-link referral information. [Conversation list](https://business-api.tiktok.com/portal/docs?id=1832184415059970)
- `GET /business/message/content/list/` requires `business_id` and `conversation_id` and returns **at most the 20 most recent messages** in that conversation. The documented request has no cursor/older-history parameter. Responses include sender/recipient, message and conversation IDs, millisecond timestamp, `message_type`, type-specific content, participants, and `message_tag.source` (including API vs app/web). This is a limited recent-history endpoint, not a verified full backfill method. URL-encode conversation IDs, especially `+` as `%2B`. [Message list](https://business-api.tiktok.com/portal/docs?id=1832184425841170)

## Media

- Outbound image: `POST /business/message/media/upload/` with `Access-Token`, multipart `business_id`, `file`, `media_type: IMAGE`; accepts **JPG/PNG up to 3 MB**, returns a `media_id` valid **30 days**. Then send `IMAGE` with that ID. Image attachment sending/receiving depends on both parties' countries. `GET /business/message/capabilities/get/` with `business_id`, `capability_types=["IMAGE_SEND"]`, `conversation_id`, and `conversation_type` returns a boolean `capability_result`; check per conversation. [Upload](https://business-api.tiktok.com/portal/docs?id=1832184437720193); [send](https://business-api.tiktok.com/portal/docs?id=1832184403754242); [capabilities](https://business-api.tiktok.com/portal/docs?id=1836061597865986)
- Incoming image **or video**: `POST /business/message/media/download/` with JSON `business_id`, `conversation_id`, `message_id`, `media_id`, `media_type: IMAGE|VIDEO`. The resulting `download_url` lasts **24 hours**; fetching it requires `x-user: <Access-Token>`. The upload endpoint supports `IMAGE` only, and the send endpoint has no `VIDEO` message type, so these pages establish video **download**, not API video send. [Download](https://business-api.tiktok.com/portal/docs?id=1832184455450626); [upload](https://business-api.tiktok.com/portal/docs?id=1832184437720193); [send](https://business-api.tiktok.com/portal/docs?id=1832184403754242)

## Rate limits and remaining gaps

- TikTok states **10 QPS** for Business Messaging API endpoints. Its platform-wide app limits also apply: Basic (default) **10 QPS / 600 QPM / 864,000 QPD**, with higher approved tiers. `40100` indicates throttling; TikTok says QPM suspensions require a **5-minute** wait and QPD resets at **00:00 UTC** next day. The actual app tier and any additional applied rule require inspection in the developer portal or TikTok support; this research did not make live API calls. [Business Messaging get started](https://business-api.tiktok.com/portal/docs?id=1832184116746305); [global rate limits](https://business-api.tiktok.com/portal/docs?id=1740029171730433); [messaging return codes](https://business-api.tiktok.com/portal/docs?id=1832184306529874)
