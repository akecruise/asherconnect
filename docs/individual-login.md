# ล็อกอินรายบุคคล

เอากลับมาเมื่อ 2026-09-15 หลังถูกถอดออกไปเมื่อ 2026-09-14 เพื่อความสะดวกตอนทดสอบ
การถอดครั้งนั้นไม่มีอยู่ในประวัติ git เพราะ repo นี้เพิ่งเริ่มจับประวัติหลังจากถอดไปแล้ว
หลักฐานของโค้ดเดิมอยู่ในไฟล์ `server.mjs.bak-preNoAuth`

## ทำไมต้องมี

`connect_private.api` อ่าน `auth.uid()` เป็นตัวตั้งทุกอย่าง — `filter='mine'` แปลตรง ๆ เป็น
`c.assignee_id = auth.uid()` ตอนที่ทั้งบริการวิ่งด้วยบัญชีกลางบัญชีเดียว `auth.uid()` จึงเป็น
บัญชีนั้นเสมอ ซึ่งไม่เคยถูก assign เคสไหน แท็บ "งานของฉัน" เลยได้ 0 เคสตลอด — ตอบถูกแล้ว
แต่ตอบคำถามผิดข้อ

**ฝั่งฐานข้อมูลไม่ต้องแก้อะไรเลย ไม่มี migration ใหม่ในงานนี้** สิทธิ์ทั้งชุด (`core.profile`,
`core.ensure_current_profile()`, `connect_private.can_read()`) ไม่เคยถูกถอด มีแต่ชั้น Node
ที่เลิกถามว่าใครเป็นคนกด

## ทำงานยังไง

- ใช้บัญชี Supabase Auth ของแต่ละคนที่มีอยู่แล้ว ไม่มีการสมัครเอง ไม่มีการให้ role ผ่านหน้าเว็บ
- ล็อกอินผ่าน `POST /auth/v1/token?grant_type=password` แล้วต้องผ่านด่านที่สองคือ
  `connect_api('bootstrap')` — คนที่มีบัญชีแต่ไม่มีแถวใน `core.profile` จะตกตั้งแต่ตอนล็อกอิน
  ไม่ใช่ตกตอนกดปุ่มแรกในหน้าจอ
- คุกกี้เก็บ **หมายเลขอ้างอิงทึบ 64 ตัวอักษร ไม่ใช่ JWT** — `HttpOnly` `SameSite=Lax`
  และมี `Secure` เมื่อ `CONNECT_PUBLIC_URL` เป็น https
  เหตุผลที่ไม่เก็บ JWT ในคุกกี้: JWT ที่หลุดออกไปแล้วเรียกคืนกลางคันไม่ได้ ส่วนหมายเลขอ้างอิง
  ลบไฟล์ทิ้งก็จบ · refresh token ต้องไม่เคยผ่านมือเบราว์เซอร์ · คุกกี้มีเพดาน 4KB
- ★ **เซสชันเก็บเป็นไฟล์ ไม่ใช่ในหน่วยความจำ** ที่ `SESSION_DIR` (ค่าเริ่มต้น `.sessions/`)
  ชื่อไฟล์เป็น sha256 ของหมายเลขอ้างอิง โหมด 600 เขียนแบบ temp+rename
  ถ้าเก็บในหน่วยความจำ การ deploy หนึ่งครั้งจะเด้งทุกคนที่กำลังพิมพ์ตอบลูกค้าออกพร้อมกันทั้งออฟฟิศ
  ใน container จึงต้องมี volume `connect-sessions` ผูกที่ `/app/.sessions` ไม่งั้นสร้าง
  container ใหม่แล้วก็หายอยู่ดี
- อายุเซสชัน 8 ชั่วโมงนับจากตอนล็อกอิน ต่ออายุไม่ได้ · access token หมุนอัตโนมัติก่อนหมดอายุ 1 นาที
- การหมุน token ถูกบังคับให้เกิดทีละครั้งต่อเซสชันด้วย Map ในหน่วยความจำ เพราะ refresh token
  ใช้ได้ครั้งเดียว — **บริการนี้จึงต้องรันสำเนาเดียว** ถ้าจะขยายเป็นหลายสำเนาต้องย้ายตัวคุมลงฐานก่อน
  ไม่ใช่แค่แชร์โฟลเดอร์เซสชันกัน
- ออกจากระบบ = ลบไฟล์เซสชันทันที แล้วค่อยแจ้ง gotrue ถอน token (ถอนไม่สำเร็จก็ยังถือว่าออกแล้ว)
- จำกัดการล็อกอิน 10 ครั้งต่ออีเมล และ 60 ครั้งต่อ IP ต่อ 15 นาที
  ★ หลัง Caddy ทุกคำขอมาจาก 127.0.0.1 หมด **ถัง IP จึงเป็นถังรวมของทั้งบริษัท ไม่ใช่รายคน**
  ตัวที่กันเดารหัสผ่านจริง ๆ คือถังรายอีเมล

## อะไรไม่ถูกแตะ

- **webhook และ worker ยังใช้ `service_role` เหมือนเดิมทุกจุด** ไม่เกี่ยวกับเซสชันเลย
  ข้อความขาเข้ายังเข้าได้แม้ไม่มีใครล็อกอินอยู่สักคน
- `channels.json` และ logic ของ webhook ไม่ถูกแก้

## ที่ยังไม่ได้ทำ / ยังพิสูจน์ไม่ได้

- **ยังไม่ deploy** ของบน VPS ยังเป็นรุ่นบัญชีกลาง
- **ยังไม่มีบัญชีพนักงานจริงสักคน** ต้องสร้างก่อน deploy ไม่ใช่หลัง ไม่งั้นทุกคนเข้าไม่ได้
  ใช้ `asher-web/scripts/create-user.mjs` และต้องเป็นคนรันเอง
- ทดสอบกับ Supabase จริงและ `docker compose build` ยังทำไม่ได้ เพราะ Docker บนเครื่อง dev ดับอยู่
- `tests/http.integration.mjs` แก้ให้ล็อกอินก่อนยิงคำสั่งแล้ว แต่ยังไม่ได้รัน เพราะต้องใช้ฐานจริง

## ทดสอบ

`node --test tests/auth.test.mjs` — ปลายทาง Supabase เป็นของจำลอง ไม่แตะฐานจริง
ไม่ส่งข้อความหาลูกค้า และไม่ทิ้งขยะ (โฟลเดอร์เซสชันสร้างใน temp แล้วลบท้ายเทสต์)
ครอบ: ตัวตนแยกกัน · คุกกี้ปลอมใช้ไม่ได้ · **รีสตาร์ตแล้วเซสชันไม่หลุด** · หมุน token ทีละครั้ง ·
ออกจากระบบแล้วใช้ซ้ำไม่ได้ · หมดอายุ 8 ชม. · กวาดไฟล์ทิ้ง · บังคับ origin · webhook ไม่ติดร่างแห ·
จำกัดจำนวนครั้งล็อกอิน
