## 7. กฎที่ได้จากเหตุนี้

1. **ห้ามรันไฟล์ sql เก่าทั้งไฟล์ลงโปรดักชัน** — ไฟล์ใน `sql/` ไม่ใช่ migration
   ถ้าต้องแก้ ให้เขียนไฟล์ใหม่ที่ต่อท้าย `ORDER.txt` แล้วรันเฉพาะไฟล์นั้น
2. **deploy จาก commit เท่านั้น** (`git archive <commit>`) ห้าม `scp` จากเวิร์กทรี
   — ของที่ยังไม่ commit จะไม่มีทางหลุดขึ้นไป และของที่ลืม commit จะโผล่ให้เห็นทันที
3. **ก่อน deploy ทุกครั้ง ทำตาราง diff กับโค้ดที่รันอยู่** (`diff -rq --strip-trailing-cr`)
   — วันนี้ตารางนี้จับได้ว่ามีของที่ใช้งานจริงแต่ไม่เคย commit ถึง 11 ไฟล์
   ★ ต้องใส่ `--strip-trailing-cr` ไม่งั้นความต่างเรื่องท้ายบรรทัดจะกลบของจริงหมด
   (สำเนาเก่ามาจาก `scp` เวิร์กทรี Windows = CRLF ส่วนของใหม่มาจาก `git archive` = LF)
4. **commit ทันทีหลัง deploy** อย่าปล่อยให้ "ของที่รันอยู่" กับ "ของที่อยู่ใน git" ต่างกันข้ามวัน
5. **ห้าม `sleep` ยาวผ่าน SSH** — เชื่อมต่อหลุดมาแล้ว 3 ครั้ง ให้รันคำสั่งสั้นซ้ำ
   หรือ `setsid nohup` ตัวเฝ้าไว้บนเซิร์ฟเวอร์แล้วมาอ่านผลเป็นระยะ
6. **ก่อนลบแอป Meta ต้องตรวจว่าอะไรใช้ token ของมันอยู่** — token, webhook subscription
   และ signature verification ผูกกับแอป ลบแล้วกระทบทันทีโดยไม่มีอะไรฟ้อง
7. `grep -c` **กับ pattern carriage return ใช้ไม่ได้** ใน shell นี้ (pattern กลายเป็นสตริงว่าง
   แล้วนับทุกบรรทัด) ตรวจท้ายบรรทัดด้วย Python แบบไบต์เท่านั้น
8. **ตรวจ schema ก่อนเชื่อผลคิวรี** — `proname='emit'` โดยไม่ระบุ schema ทำให้สรุปผิดมาแล้ว
